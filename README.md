# Enactus OS

Платформа для управления организациями на Django, Django Ninja и PostgreSQL 16. Пользователь входит по сессии и выбирает рабочую область из списка организаций, в которых у него есть активное членство.

## Локальный запуск

Из корня репозитория с Python 3 и Docker Compose с поддержкой `up --wait`:

```bash
python3 scripts/init-env.py
docker compose config --quiet
docker compose up --build --wait
docker compose exec web python manage.py createsuperuser
```

Первую команду выполняют один раз. Она создаёт локальный `.env` из `.env.example` со случайными ключом Django и паролем PostgreSQL. Если файл уже есть, переходите к проверке Compose.

Откройте страницу входа и введите данные созданного пользователя. При запуске веб-сервис сам применяет миграции. PostgreSQL принимает соединения внутри сети Compose и хранит данные в именованном томе проекта.

- [Страница входа](http://127.0.0.1:8002/accounts/login/)
- [Мои организации](http://127.0.0.1:8002/organizations/)
- [Мои приглашения](http://127.0.0.1:8002/organizations/invitations/)
- [Django Admin](http://127.0.0.1:8002/admin/)
- [Healthcheck API](http://127.0.0.1:8002/api/v1/health/)
- [OpenAPI в режиме разработки](http://127.0.0.1:8002/api/v1/openapi.json)

Если порт 8002 занят, измените `WEB_PORT` в `.env`. Сохраните `127.0.0.1` в `DJANGO_ALLOWED_HOSTS` для проверки здоровья веб-сервиса. Compose предназначен для локальной разработки. После инициализации PostgreSQL изменение пароля в `.env` требует отдельной смены пароля роли в самой БД.

## Рабочая область

Выберите организацию в боковой панели. В ней собраны обзор, структура, доступный каталог участников, проекты и настройки организации. Список «Мои организации», личные приглашения в организации и подразделения, профиль и настройки интерфейса доступны независимо от выбранной организации.

Каталог организации показывает активных участников с активными аккаунтами. Он доступен, если владелец включил видимость каталога всей организации или у пользователя есть разрешение `departments.directory.read` на уровне организации.

В профиле отображаются данные вашей учётной записи. В личных настройках можно изменить тему интерфейса. В «Настройках организации» владелец с активным членством меняет правила вступления. Видимость каталога по-прежнему настраивается на странице участников подразделения.

## Создание организации

Войдите под созданным суперпользователем, откройте страницу «Мои организации» и заполните форму «Новая организация». Для отправки формы нужен JavaScript. Создатель становится владельцем и активным участником новой организации.

Обычному пользователю доступно создание после выдачи разрешения `organizations.add_organization` в Django Admin. Это разрешение даёт право создать организацию. Для просмотра каждой организации необходимо активное членство, в том числе у суперпользователя.

## Вступление в организацию

Выберите организацию и откройте «Приглашения и заявки» в боковой панели. В «Настройках организации» владелец выбирает способ вступления: по приглашениям, по заявкам или обоими способами. По умолчанию доступны приглашения. Владелец может выдать или отозвать право управления участниками у активного участника этой организации.

- **Приглашения.** Владелец или участник с правом управления приглашает существующий активный аккаунт по имени пользователя. Получатель может принять или отклонить приглашение в личном списке. Ссылку, показанную при создании, можно передать получателю вручную. Приглашение действует 7 дней и может быть отозвано. Письма не отправляются.
- **Заявки.** Если организация принимает заявки, на странице управления доступна подписанная ссылка. Пользователь входит в свой аккаунт и подаёт заявку по этой ссылке. Владелец или участник с правом управления принимает решение на странице «Приглашения и заявки». После одобрения рабочая область появляется в списке «Мои организации».

Изменение правил вступления сразу влияет на открытые приглашения и заявки. Когда способ выключен, принять приглашение или одобрить заявку этого типа нельзя. Отзыв приглашения и отрицательное решение по заявке остаются доступны.

## Структура организации

Выберите организацию и откройте «Подразделения» в боковой панели. Дерево доступно активным участникам организации. Для загрузки дерева нужен JavaScript. Стрелка у подразделения раскрывает или сворачивает ветку. Поиск по названию временно раскрывает путь к совпадениям. Архивные подразделения можно включить через «Фильтры» → «Показывать архивные».

Кнопка «Новое подразделение» с плюсом открывает форму создания. Пункт «Добавить дочернее» в меню «⋯» сразу выбирает подразделение родителем. Оставьте поле родителя пустым, чтобы создать корневое подразделение или перенести существующее в корень. После создания дерево обновляется и раскрывает путь к новому подразделению.

Меню «⋯» показывает доступные действия. Редактирование и перемещение открывают диалог, архивирование требует подтверждения для всей ветки. Архивирование сохраняет записи подразделения и его потомков.

### Участники подразделения

Если каталог подразделения вам доступен, откройте его по названию подразделения или через «Открыть участников» в меню. Каталог показывает каждого человека один раз и перечисляет полные пути к подразделениям, в которых он состоит в выбранной ветке. Человек может состоять в нескольких подразделениях.

Владелец выбирает видимость каталога. По умолчанию участникам доступны ветки, в которых у них есть прямое или вложенное членство. В режиме «Всю организацию» активные участники могут открывать каталог любого действующего подразделения и видеть людей вне выбранной ветки. Владелец и делегированные управляющие видят каталог всей организации в обоих режимах.

Участники с соответствующими разрешениями могут приглашать видимых им участников организации в подразделение и завершать прямые членства. Получатель принимает или отклоняет приглашение в отдельном [списке приглашений в подразделения](http://127.0.0.1:8002/organizations/department-invitations/). Архивирование подразделения или деактивация членства в организации закрывает связанные членства в подразделениях и отзывает ожидающие приглашения.

## Роли и доступ

Откройте «Роли и доступ» в боковой панели выбранной организации. Активные участники могут проверить свои разрешения в организации или в выбранном подразделении. Владелец и участники с правом управления ролями могут создавать роли из набора разрешений, назначать их и вести список должностей. Должность служит подписью и не влияет на доступ.

В форме создания роли можно начать с шаблона «Координатор подразделения» или «Наблюдатель ролей». Шаблон заполняет поля формы. Вы можете проверить набор разрешений и сохранить роль.

Роль можно назначить активному участнику на всю организацию или на подразделение, в котором он состоит напрямую. Для каждого разрешения роли отдельно настраивается распространение на дочерние подразделения. Делегированное управление ролями ограничено правами управляющего и их областью. Правила вступления, видимость каталога и прежнее делегирование управления участниками по-прежнему меняет владелец.

## Проекты

Откройте «Проекты» в боковой панели выбранной организации. Здесь доступны список и карточки проектов, которые вы вправе просматривать. При наличии разрешений можно создать проект, указать статус и плановые даты, назначить руководителя и связать проект с ответственным и участвующими подразделениями.

Проект может существовать без ответственного подразделения. Для такого проекта действуют разрешения уровня организации. Доступ к проекту с действующим ответственным подразделением может давать роль в этом подразделении или унаследованная роль его предка. Руководитель и участвующие подразделения указываются отдельно от разрешений. Архивные проекты остаются доступны для чтения в рамках тех же правил.

### Команда и запросы специалистов

Из карточки проекта откройте «Команда». Руководитель своего проекта с разрешением на запрос специалистов может сохранить черновик, указав подразделение, число специалистов и описание работ, а затем отправить запрос. Владелец организации может выполнить эти действия, если руководитель недоступен.

Распределяющий открывает «Запросы сотрудников» в боковой панели, выбирает входящий запрос и выделяет подходящих специалистов из доступной ветки либо отклоняет запрос с комментарием. В списке кандидатов отображаются только названия проектов, которые распределяющий вправе видеть. Запрос показывает число принятых и ожидающих назначений и доступную историю.

В настройках организации владелец выбирает прямое назначение или приглашение с подтверждением. В режиме приглашений специалист отвечает во входящих «В проекты». Ожидающее приглашение резервирует место, а прямое членство появляется после принятия. Активное членство даёт право читать карточку проекта и состав команды. Прекращение участия в проекте сохраняет членства в организации и подразделении.

## Задачи

В боковой панели организации откройте «Задачи» или «Мои задачи». Из карточки проекта можно перейти к его задачам. Список поддерживает поиск и фильтры, а карточка показывает состояние, приоритет, сроки, основного исполнителя и соисполнителей. Задача может быть связана с проектом и подразделением либо существовать самостоятельно.

«Мои задачи» включает доступные задачи, в которых вы основной исполнитель или активный соисполнитель. В списке отмечаются просроченные и предстоящие сроки открытых задач. Если задача относится к проекту, для её просмотра также требуется доступ к проекту.

Карточка показывает основные сведения и предупреждения рядом с заголовком. Дополнительные сведения доступны в раскрываемых разделах «Описание и детали» и «Соисполнители». Из меню «⋯» доступны редактирование, изменение статуса и управление исполнителями в пределах ваших прав. Формы открываются в диалогах. Подзадачи, чек-листы, зависимости и проверка результата остаются в отдельных секциях карточки.

Владелец выбирает режим назначения в настройках организации. При прямом назначении уполномоченный руководитель своего проекта выбирает исполнителей из активных участников проекта. Для самостоятельной задачи кандидатами служат активные участники организации. В режиме «Через подразделение» выберите действующее ответственное подразделение и нажмите «Направить на распределение» в карточке задачи. Уполномоченный распределяющий открывает очередь «Распределение задач» и выбирает основного исполнителя. Для проектной задачи кандидат также должен состоять в проекте.

В режиме прямого назначения основного исполнителя можно выбрать сразу в диалоге создания задачи или подзадачи, если действие разрешено. При выборе проекта или подразделения список кандидатов обновляется. Создание и назначение сохраняются вместе.

Основной исполнитель с разрешением на отправку может представить результат в карточке задачи. К результату можно добавить комментарий и ссылки. Маршрут проверки задаётся для организации и при наличии прав переопределяется в проекте или задаче. При двух этапах сначала проверяет подразделение, затем руководитель проекта. Для самостоятельной задачи можно использовать проверку подразделением или назначить конкретного проверяющего.

Проверяющий открывает очередь «Проверка задач» и принимает результат либо возвращает его на доработку с пояснением. После возврата новая отправка начинает маршрут с первого этапа. Карточка сохраняет историю назначения, версии результата и решения по этапам.

### Подзадачи и чек-листы

В карточке задачи откройте «Подзадачи», чтобы просмотреть дерево или добавить поручение. Подзадача имеет собственную карточку, исполнителей, сроки, статус и маршрут проверки. При создании форма предлагает проект и подразделение родителя. Завершение подзадач само по себе не закрывает родительскую задачу.

В разделе «Чек-листы» можно создать несколько списков, добавить пункт через компактное поле, отметить его одним нажатием, изменить порядок и посмотреть прогресс. Пункт можно преобразовать в полноценную подзадачу. Такая подзадача начинает в ожидании, даже если исходный пункт был отмечен выполненным. Обратное преобразование требует подтверждения и доступно для простой подзадачи без значимых данных. Исходная запись архивируется, а преобразование сохраняется в истории.

### Зависимости задач

В карточке задачи откройте «Зависимости» и выберите задачу, от которой зависит работа. «Предупреждение» сообщает о незавершённой предшествующей задаче. «Блокирует выполнение» не даёт начать работу или отправить результат прямо из ожидания, пока предшествующая задача не завершена. Отмена предшествующей задачи блокировку не снимает.

Если доступ к предшествующей задаче закрыт, карточка показывает наличие зависимости без её названия и ссылки. Задачу с входящей или исходящей зависимостью нельзя преобразовать в пункт чек-листа.

### Списки проектов и задач

Переключатель «Список / Карточки» меняет представление без перезагрузки. Браузер запоминает выбор отдельно для проектов и задач. Поиск и панель «Фильтры» работают в обоих представлениях. Для задач сохраняется серверная пагинация.

Кнопка с плюсом открывает форму создания в диалоге. После сохранения список обновляется, а при ошибке введённые данные остаются в форме. Через меню «⋯» можно открыть объект, перейти к редактированию или архивировать его после подтверждения. Набор действий зависит от разрешений пользователя.

### Приоритеты задач

В боковой панели организации откройте «Рабочие процессы» → «Приоритеты». Уполномоченный участник может добавить уровень, изменить его название, цвет, ранг и порядок в списке, назначить уровень по умолчанию или архивировать неиспользуемый пользовательский уровень.

В списке задач выберите приоритет в фильтрах или включите сортировку по рангу. Задачи с большим рангом идут первыми. Порядок в справочнике влияет на расположение вариантов выбора. Срок задачи задаётся отдельно.

### Пользовательские статусы и переходы

В разделе «Рабочие процессы» доступны «Пользовательские статусы» и «Переходы между статусами». При наличии разрешений можно добавить статус, выбрать его системный этап, цвет и порядок, а также назначить его статусом по умолчанию для этапа. Для перехода настраиваются доступность основному исполнителю и дополнительные разрешения.

Карточка задачи показывает текущий пользовательский статус и доступные переходы. Список задач поддерживает фильтры по пользовательскому статусу и системному этапу. Отправка на проверку, возврат и завершение выполняются через маршрут согласования. Строгая зависимость по-прежнему блокирует начало работы.

## Календарь

Выберите организацию и откройте «Календарь» в боковой панели. Переключайте «Месяц», «Неделя» и «День», используйте стрелки периода и кнопку «Сегодня». Нажмите на дату или «Ещё» в месяце, чтобы открыть расписание этого дня. В «Фильтрах» доступны тип записи, проект, подразделение, показ архива и часовой пояс календаря. При первом открытии используется месяц и часовой пояс браузера. Выбранные режим и пояс запоминаются в браузере.

Кнопка «Новое событие» открывает форму встречи или мероприятия. Для записи «Весь день» укажите первый и последний день включительно. Обычная встреча может продолжаться несколько дней. В карточке события доступны редактирование, отмена и архивирование в пределах ваших прав.

Для ручной проверки в тестовой организации создайте встречу со временем и мероприятие на весь день. Проверьте их в каждом режиме и смените часовой пояс через фильтры. Затем откройте дедлайн задачи из календаря, измените его в карточке задачи и обновите календарь. Запись должна перейти на новую дату. У задачи без дедлайна календарной записи нет.

### Приглашения на мероприятия

В карточке запланированного события откройте «Участники» и нажмите «Пригласить участников». Выберите людей, подразделения, проектные команды или всю организацию в пределах ваших прав. Для подразделения можно включить дочерние отделы. Нажмите «Рассчитать аудиторию», проверьте число уникальных получателей и отправьте приглашения. Чтобы добавить людей, которые присоединились к выбранным группам позже, используйте «Обновить аудиторию». Для повторного приглашения отозванных есть отдельный флажок.

Приглашённый открывает «Мои приглашения на мероприятия» в боковой панели организации. Информационное событие можно просмотреть. Для необязательного или обязательного RSVP доступны «Приду», «Не приду» и «Пока не знаю». В обязательном режиме отсутствие ответа отмечается как «Ожидается ответ». После переноса события ранее ответившие могут подтвердить выбор заново. Организатор видит текущие ответы и историю.

Фильтр «Предстоящие» оставляет серии, у которых ещё есть запланированная встреча с окончанием в будущем. Завершившиеся серии остаются доступны в общем списке с сохранёнными ответами.

Для ручной проверки используйте тестовое событие и два аккаунта. Пригласите одного человека лично и через группу, проверьте одно приглашение в его личном списке и отправьте ответ. Затем измените время события из аккаунта организатора и проверьте запрос повторного ответа и сохранение предыдущего ответа в истории.

### Повторяющиеся события

В форме «Новое событие» откройте «Повторение», выберите частоту, интервал и условие окончания. Для еженедельной встречи можно выбрать несколько дней. Для ежемесячной серии пропускаются месяцы, в которых нет исходного числа.

Из календаря откройте нужную встречу и выберите «Редактировать только эту встречу» или «Отменить только эту встречу». Действия в разделе «Вся серия» меняют общее расписание. Чтобы увидеть отменённые даты, включите «Показывать отменённые повторения» в фильтрах.

В личном приглашении можно ответить на серию и отдельно на выбранную встречу. Для ручной проверки в тестовой организации создайте еженедельную серию, пригласите второй аккаунт и ответьте «Приду» на серию. Перенесите одну встречу, проверьте новую дату и запрос повторного подтверждения. Выберите для неё «Не приду» и убедитесь, что остальные встречи по-прежнему используют общий ответ.

## Уведомления

Откройте «Уведомления» в боковой панели. Личный список объединяет записи из доступных организаций. Можно выбрать «Непрочитанные», категорию или организацию. Счётчик обновляется раз в минуту на видимой вкладке и при возвращении к ней.

Кнопка «Прочитано» меняет отметку одной записи. Кнопка «Отметить все как прочитанные» охватывает все страницы текущей выборки. «Открыть» проверяет доступ к объекту и отмечает уведомление прочитанным перед переходом. При утрате доступа запись остаётся в списке с нейтральным текстом и без ссылки. Прочтение уведомления о встрече не меняет ответ RSVP.

Для ручной проверки в тестовой организации назначьте задачу другому аккаунту. Во втором аккаунте откройте уведомление, проверьте переход в карточку и счётчик. Проверьте также личное приглашение в организацию до вступления.

### Правила и напоминания

В «Настройках организации → Уведомления» владелец или участник с разрешением `notifications.manage` управляет категориями, типами уведомлений и интервалами напоминаний. Напоминания включаются явно. В «Личных настройках уведомлений» выберите организацию, категории, напоминания, часовой пояс IANA и при необходимости тихие часы. Личные настройки действуют в пределах политики организации.

Для ручной проверки включите напоминание о задаче и назначьте её тестовому участнику. Проверьте его ленту после наступления выбранного интервала. Для события на весь день включите интервал «За день». Напоминание планируется на предыдущий день по часовому поясу события, на время из политики организации. Проверьте также, что актуальный отказ RSVP исключает напоминание.

Compose запускает сервис `worker` после готовности БД и веб-сервиса. По умолчанию он выполняет итерацию каждые 15 секунд. В тестовой среде одну итерацию можно запустить командой `docker compose exec web python manage.py notification_worker --once`. Для диагностики проверьте `docker compose logs worker`. После устранения причины сбоя команда `docker compose exec web python manage.py retry_notifications --limit 100` повторно обрабатывает недоставленные события, включая окончательно неуспешные.

## Журнал действий

Откройте «Журнал действий» в боковой панели организации. Владелец видит журнал в пределах текущих прав на связанные объекты. Делегированному участнику можно выдать просмотр по веткам подразделений. Для сравнения значений требуется отдельное разрешение на подробности.

Введите название доступного объекта или раскройте «Фильтры», чтобы выбрать инициатора, действие, категорию объекта, проект, подразделение или диапазон дат. Даты и время указаны в UTC. Кнопка «Подробности» открывает сведения о записи и сравнение «Было» и «Стало». Для чувствительных полей журнал показывает сам факт изменения. История накапливается с момента включения аудита.

## Проверки

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test
curl --fail http://127.0.0.1:8002/api/v1/health/
```

Штатная команда `manage.py test` создаёт отдельную базу с уникальным именем `test_enactus_*` на каждый прогон. Защита PostgreSQL проверяет имя перед созданием и удалением и прекращает прогон, если такая база уже существует. После тестов Django удаляет только временную базу, созданную этим прогоном. Запускайте тесты последовательно, без `--keepdb` и `--parallel`. Созданием и очисткой управляет `manage.py test`.

Для остановки проекта с сохранением данных используйте `docker compose stop`.

## Резервная копия PostgreSQL

Сохраните дамп локальной БД в защищённом каталоге. Для проверки восстановления команды создают отдельную временную базу с уникальным именем.

```bash
umask 077
backup_file="$(mktemp "${TMPDIR:-/tmp}/enactus-backup.XXXXXXXX.dump")"
docker compose exec -T db sh -c 'pg_dump -Fc -U "$POSTGRES_USER" "$POSTGRES_DB"' > "$backup_file"
```

После успешного создания дампа:

```bash
restore_db="enactus_restore_$(date +%Y%m%d_%H%M%S)"
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" "$1"' sh "$restore_db" &&
  docker compose exec -T db sh -c 'pg_restore --exit-on-error -U "$POSTGRES_USER" -d "$1"' sh "$restore_db" < "$backup_file"
```

### Если отсутствует рабочая база

Проверка готовности PostgreSQL выполняет запрос к рабочей базе по TCP с ролью и паролем из настроек. Если контейнер запущен, но база недоступна, проверьте состояние проекта и наличие базы через служебную БД `postgres`:

```bash
docker compose ps
docker compose exec -T db sh -c 'psql -X -w -U "$POSTGRES_USER" -d postgres -l'
```

Сверьте ожидаемое имя с `POSTGRES_DB` в локальном `.env`. Перед восстановлением подтвердите отсутствие рабочей базы и согласуйте с владельцем, какой дамп восстанавливать. Остановите веб-сервис на время восстановления. Команда `createdb` прервётся, если база уже существует:

```bash
docker compose stop web
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" --maintenance-db=postgres "$POSTGRES_DB"' &&
  docker compose exec -T db sh -c 'pg_restore --single-transaction --exit-on-error -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < "$backup_file"
```

После успешного восстановления запустите `docker compose up --build --wait`. Если подтверждено, что контур был пустым, по согласованию можно создать пустую рабочую базу той же командой `createdb` и запустить Compose для применения миграций. Именованный том и существующие базы сохраняются при обеих процедурах.

## Структура

- `config/` содержит настройки Django, маршруты и Ninja API.
- `apps/accounts/` содержит модель глобального пользователя и её миграцию.
- `apps/organizations/` содержит модели организаций и членств, правила доступа, API и серверные представления.
- `apps/departments/` содержит дерево подразделений, операции управления и ограничения PostgreSQL.
- `apps/access/` содержит роли, должности, назначения и серверную проверку разрешений.
- `apps/projects/` содержит проекты, связи с подразделениями и операции управления проектами.
- `apps/tasks/` содержит задачи, соисполнителей, фильтры и операции управления задачами.
- `apps/calendar_app/` содержит события, объединённое представление календаря и операции управления встречами и мероприятиями.
- `apps/notifications/` содержит внутреннюю очередь доставки и личный центр уведомлений.
- `apps/audit/` содержит сервис записи аудита, проверку доступа к записям и журнал действий.
- `templates/` и `static/` содержат HTML, общую систему стилей, переключатель темы и JavaScript организаций.
- `tests/` содержит тесты API, сессионной аутентификации и границ доступа между организациями.
- `docs/` содержит [ТЗ](docs/TECHNICAL_SPEC.md), [решения](docs/DECISIONS.md), [API](docs/API.md), [схему данных](docs/ERD.md) и [статус](docs/STATUS.md).
