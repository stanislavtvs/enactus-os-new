# Enactus OS

Платформа для управления организациями на Django, Django Ninja и PostgreSQL 16. Пользователь входит по сессии и выбирает рабочую область из списка организаций, в которых у него есть активное членство.

## Локальный запуск

Из корня репозитория с Python 3 и Docker Compose с поддержкой `up --wait`:

```bash
python3 scripts/init-env.py
docker compose config --quiet
docker compose up --build --wait
docker compose exec web python manage.py createsuperuser
```

Первую команду выполняют один раз. Она создаёт локальный `.env` из `.env.example` со случайными ключом Django и паролем PostgreSQL. Если файл уже есть, переходите к проверке Compose.

Откройте страницу входа и введите данные созданного пользователя. При запуске веб-сервис сам применяет миграции. PostgreSQL принимает соединения внутри сети Compose и хранит данные в именованном томе проекта.

- [Страница входа](http://127.0.0.1:8002/accounts/login/)
- [Мои организации](http://127.0.0.1:8002/organizations/)
- [Мои приглашения](http://127.0.0.1:8002/organizations/invitations/)
- [Django Admin](http://127.0.0.1:8002/admin/)
- [Healthcheck API](http://127.0.0.1:8002/api/v1/health/)
- [OpenAPI в режиме разработки](http://127.0.0.1:8002/api/v1/openapi.json)

Если порт 8002 занят, измените `WEB_PORT` в `.env`. Сохраните `127.0.0.1` в `DJANGO_ALLOWED_HOSTS` для проверки здоровья веб-сервиса. Compose предназначен для локальной разработки. После инициализации PostgreSQL изменение пароля в `.env` требует отдельной смены пароля роли в самой БД.

## Рабочая область

Выберите организацию в боковой панели. В ней собраны обзор, структура, доступный каталог участников, проекты и настройки организации. Список «Мои организации», личные приглашения в организации и подразделения, профиль и настройки интерфейса доступны независимо от выбранной организации.

Каталог организации показывает активных участников с активными аккаунтами. Он доступен, если владелец включил видимость каталога всей организации или у пользователя есть разрешение `departments.directory.read` на уровне организации.

В профиле отображаются данные вашей учётной записи. В личных настройках можно изменить тему интерфейса. В «Настройках организации» владелец с активным членством меняет правила вступления. Видимость каталога по-прежнему настраивается на странице участников подразделения.

## Создание организации

Войдите под созданным суперпользователем, откройте страницу «Мои организации» и заполните форму «Новая организация». Для отправки формы нужен JavaScript. Создатель становится владельцем и активным участником новой организации.

Обычному пользователю доступно создание после выдачи разрешения `organizations.add_organization` в Django Admin. Это разрешение даёт право создать организацию. Для просмотра каждой организации необходимо активное членство, в том числе у суперпользователя.

## Вступление в организацию

Выберите организацию и откройте «Приглашения и заявки» в боковой панели. В «Настройках организации» владелец выбирает способ вступления: по приглашениям, по заявкам или обоими способами. По умолчанию доступны приглашения. Владелец может выдать или отозвать право управления участниками у активного участника этой организации.

- **Приглашения.** Владелец или участник с правом управления приглашает существующий активный аккаунт по имени пользователя. Получатель может принять или отклонить приглашение в личном списке. Ссылку, показанную при создании, можно передать получателю вручную. Приглашение действует 7 дней и может быть отозвано. Письма не отправляются.
- **Заявки.** Если организация принимает заявки, на странице управления доступна подписанная ссылка. Пользователь входит в свой аккаунт и подаёт заявку по этой ссылке. Владелец или участник с правом управления принимает решение на странице «Приглашения и заявки». После одобрения рабочая область появляется в списке «Мои организации».

Изменение правил вступления сразу влияет на открытые приглашения и заявки. Когда способ выключен, принять приглашение или одобрить заявку этого типа нельзя. Отзыв приглашения и отрицательное решение по заявке остаются доступны.

## Структура организации

Выберите организацию и откройте «Подразделения» в боковой панели. Дерево доступно активным участникам организации. Для загрузки дерева нужен JavaScript. Переключатель «Показывать архивные» добавляет архивные подразделения в дерево.

Создание, переименование, перемещение и архивирование доступны в пределах выданных разрешений. Оставьте родителя пустым, чтобы создать корневое подразделение или перенести существующее в корень. Архивирование распространяется на выбранное подразделение и всех его потомков. Записи сохраняются.

### Участники подразделения

В структуре выберите «Участники» рядом с нужным подразделением. Каталог показывает каждого человека один раз и перечисляет полные пути к подразделениям, в которых он состоит в выбранной ветке. Человек может состоять в нескольких подразделениях.

Владелец выбирает видимость каталога. По умолчанию участникам доступны ветки, в которых у них есть прямое или вложенное членство. В режиме «Всю организацию» активные участники могут открывать каталог любого действующего подразделения и видеть людей вне выбранной ветки. Владелец и делегированные управляющие видят каталог всей организации в обоих режимах.

Участники с соответствующими разрешениями могут приглашать видимых им участников организации в подразделение и завершать прямые членства. Получатель принимает или отклоняет приглашение в отдельном [списке приглашений в подразделения](http://127.0.0.1:8002/organizations/department-invitations/). Архивирование подразделения или деактивация членства в организации закрывает связанные членства в подразделениях и отзывает ожидающие приглашения.

## Роли и доступ

Откройте «Роли и доступ» в боковой панели выбранной организации. Активные участники могут проверить свои разрешения в организации или в выбранном подразделении. Владелец и участники с правом управления ролями могут создавать роли из набора разрешений, назначать их и вести список должностей. Должность служит подписью и не влияет на доступ.

В форме создания роли можно начать с шаблона «Координатор подразделения» или «Наблюдатель ролей». Шаблон заполняет поля формы. Вы можете проверить набор разрешений и сохранить роль.

Роль можно назначить активному участнику на всю организацию или на подразделение, в котором он состоит напрямую. Для каждого разрешения роли отдельно настраивается распространение на дочерние подразделения. Делегированное управление ролями ограничено правами управляющего и их областью. Правила вступления, видимость каталога и прежнее делегирование управления участниками по-прежнему меняет владелец.

## Проекты

Откройте «Проекты» в боковой панели выбранной организации. Здесь доступны список и карточки проектов, которые вы вправе просматривать. При наличии разрешений можно создать проект, указать статус и плановые даты, назначить руководителя и связать проект с ответственным и участвующими подразделениями.

Проект может существовать без ответственного подразделения. Для такого проекта действуют разрешения уровня организации. Доступ к проекту с действующим ответственным подразделением может давать роль в этом подразделении или унаследованная роль его предка. Руководитель и участвующие подразделения указываются отдельно от разрешений. Архивные проекты остаются доступны для чтения в рамках тех же правил.

### Команда и запросы специалистов

Из карточки проекта откройте «Команда». Руководитель своего проекта с разрешением на запрос специалистов может сохранить черновик, указав подразделение, число специалистов и описание работ, а затем отправить запрос. Владелец организации может выполнить эти действия, если руководитель недоступен.

Распределяющий открывает «Запросы сотрудников» в боковой панели, выбирает входящий запрос и выделяет подходящих специалистов из доступной ветки либо отклоняет запрос с комментарием. В списке кандидатов отображаются только названия проектов, которые распределяющий вправе видеть. Запрос показывает число принятых и ожидающих назначений и доступную историю.

В настройках организации владелец выбирает прямое назначение или приглашение с подтверждением. В режиме приглашений специалист отвечает во входящих «В проекты». Ожидающее приглашение резервирует место, а прямое членство появляется после принятия. Активное членство даёт право читать карточку проекта и состав команды. Прекращение участия в проекте сохраняет членства в организации и подразделении.

## Задачи

В боковой панели организации откройте «Задачи» или «Мои задачи». Из карточки проекта можно перейти к его задачам. Список поддерживает поиск и фильтры, а карточка показывает состояние, приоритет, сроки, основного исполнителя и соисполнителей. Задача может быть связана с проектом и подразделением либо существовать самостоятельно.

«Мои задачи» включает доступные задачи, в которых вы основной исполнитель или активный соисполнитель. В списке отмечаются просроченные и предстоящие сроки открытых задач. Если задача относится к проекту, для её просмотра также требуется доступ к проекту.

Владелец выбирает режим назначения в настройках организации. При прямом назначении уполномоченный руководитель своего проекта выбирает исполнителей из активных участников проекта. Для самостоятельной задачи кандидатами служат активные участники организации. В режиме «Через подразделение» задача создаётся без исполнителя. Маршрут распределения через подразделение предусмотрен фазой 5.2.

## Проверки

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test
curl --fail http://127.0.0.1:8002/api/v1/health/
```

Штатная команда `manage.py test` создаёт отдельную базу с уникальным именем `test_enactus_*` на каждый прогон. Защита PostgreSQL проверяет имя перед созданием и удалением и прекращает прогон, если такая база уже существует. После тестов Django удаляет только временную базу, созданную этим прогоном. Запускайте тесты последовательно, без `--keepdb` и `--parallel`. Созданием и очисткой управляет `manage.py test`.

Для остановки проекта с сохранением данных используйте `docker compose stop`.

## Резервная копия PostgreSQL

Сохраните дамп локальной БД в защищённом каталоге. Для проверки восстановления команды создают отдельную временную базу с уникальным именем.

```bash
umask 077
backup_file="$(mktemp "${TMPDIR:-/tmp}/enactus-backup.XXXXXXXX.dump")"
docker compose exec -T db sh -c 'pg_dump -Fc -U "$POSTGRES_USER" "$POSTGRES_DB"' > "$backup_file"
```

После успешного создания дампа:

```bash
restore_db="enactus_restore_$(date +%Y%m%d_%H%M%S)"
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" "$1"' sh "$restore_db" &&
  docker compose exec -T db sh -c 'pg_restore --exit-on-error -U "$POSTGRES_USER" -d "$1"' sh "$restore_db" < "$backup_file"
```

### Если отсутствует рабочая база

Проверка готовности PostgreSQL выполняет запрос к рабочей базе по TCP с ролью и паролем из настроек. Если контейнер запущен, но база недоступна, проверьте состояние проекта и наличие базы через служебную БД `postgres`:

```bash
docker compose ps
docker compose exec -T db sh -c 'psql -X -w -U "$POSTGRES_USER" -d postgres -l'
```

Сверьте ожидаемое имя с `POSTGRES_DB` в локальном `.env`. Перед восстановлением подтвердите отсутствие рабочей базы и согласуйте с владельцем, какой дамп восстанавливать. Остановите веб-сервис на время восстановления. Команда `createdb` прервётся, если база уже существует:

```bash
docker compose stop web
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" --maintenance-db=postgres "$POSTGRES_DB"' &&
  docker compose exec -T db sh -c 'pg_restore --single-transaction --exit-on-error -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < "$backup_file"
```

После успешного восстановления запустите `docker compose up --build --wait`. Если подтверждено, что контур был пустым, по согласованию можно создать пустую рабочую базу той же командой `createdb` и запустить Compose для применения миграций. Именованный том и существующие базы сохраняются при обеих процедурах.

## Структура

- `config/` содержит настройки Django, маршруты и Ninja API.
- `apps/accounts/` содержит модель глобального пользователя и её миграцию.
- `apps/organizations/` содержит модели организаций и членств, правила доступа, API и серверные представления.
- `apps/departments/` содержит дерево подразделений, операции управления и ограничения PostgreSQL.
- `apps/access/` содержит роли, должности, назначения и серверную проверку разрешений.
- `apps/projects/` содержит проекты, связи с подразделениями и операции управления проектами.
- `apps/tasks/` содержит задачи, соисполнителей, фильтры и операции управления задачами.
- `templates/` и `static/` содержат HTML, общую систему стилей, переключатель темы и JavaScript организаций.
- `tests/` содержит тесты API, сессионной аутентификации и границ доступа между организациями.
- `docs/` содержит [ТЗ](docs/TECHNICAL_SPEC.md), [решения](docs/DECISIONS.md), [API](docs/API.md), [схему данных](docs/ERD.md) и [статус](docs/STATUS.md).
